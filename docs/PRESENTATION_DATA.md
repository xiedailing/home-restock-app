## 本輪僅整理資料的範圍

檢查基準為 `8e5ca25`。既有產生器已符合兩個空間、六項用品的確認規格，因此本輪不再修改產生器或任何產品程式，僅補強資料契約測試與本文件。Vue、UI、樣式、Router、BottomNav、Pinia 正式業務、日期演算法、延後與10秒通知流程均不改動。

## 手動套用（不會自動操作既有瀏覽器）

僅允許 origin：

`https://home-restock-app-git-feature-native-browser-n-f5352f-xiedailing.vercel.app`

1. 部署本分支後，在該 Preview 設定頁點「展示資料初始化／還原」，或自行開啟 `/?demoSetup=1`。
2. 關閉其他補補分頁，包含舊部署版本、相同 Preview 的分頁與視窗。初始化頁不掛載 App、Router、Pinia 或通知排程。
3. 點「下載目前資料備份」。檔案包含用品／空間、catalog、站內通知、原生通知任務與目錄交易紀錄，請自行保管。
4. 勾選已備份及關閉其他分頁，輸入「確認」。
5. 點「建立／重置六項展示用品」。成功提示後點「返回購買清單」。
6. 重新主動啟用通知 Demo。瀏覽器通知權限、推播開關與提醒門檻保留；不自動打開任何原本關閉的推播偏好。

再次執行同一流程即可回到新的初始狀態，日期以該次建立當天為準。每次操作後必須重新下載備份及確認才能再操作。

### 還原操作前資料

初始化會在 `home-restock:v1:presentation-backup` 保留最近一次成功嘗試操作前的完整原始存檔。重新進入操作頁，先下載目前資料並確認，再點「還原上次操作前的資料」。恢復用品、空間與 catalog，但不恢復舊 Demo 任務或舊通知中心紀錄。若備份有有效的正式延後日期，正式排程仍可依原規則重建；這不等同於重送舊 Demo。

還原操作本身也會備份當前資料，所以上一份站內備份會被替換。下載的 JSON 是額外離線備份，本版沒有任意 JSON 匯入入口；需要更早備份時，應先驗證格式與資料關聯，再另行安排還原，不直接貼入 localStorage。

## 安全性與限制

- `presentationAccess.js`：指定 Preview 的一般新版分頁，整個生命週期持有共享 Web Lock；初始化需取得獨占鎖，其他一般分頁存在時拒絕。從 BFCache 返回的頁面強制重載，避免使用失去鎖後的舊 store。
- 初始化再按既有順序取得 `bubu-native-reminders` 與 `bubu-items-write`；下載後資料有變動會拒絕操作，要求重新備份，避免兩個初始化頁用舊確認覆蓋彼此。
- 不支援 Web Locks 時拒絕初始化。正式 Production、未知 origin 不會提供入口，操作 API 同樣拒絕；環境變數無法繞過白名單。
- Web Locks 只能協調有遵守同一協定的程式。較舊部署的已開啟分頁沒有生命週期共享鎖，因此必須先關閉所有舊分頁；不能宣稱完全阻擋舊程式、開發者工具或外部寫入。
- localStorage 不提供跨 key 原子交易。`presentationTransaction.js` 先保存原始備份及 `prepared` 日誌，再寫所有相關 key，最後標記 `committed`。中斷的 prepared 回滾，committed 完成新資料；App／stores 讀取前先復原。只有成功後才回到一般 App。
- 若配額／儲存權限造成回滾也失敗，保留日誌，阻止混合資料載入；恢復儲存空間後重新開啟。不能保證瀏覽器清除整個網站資料、磁碟毀損時仍能復原，離線下載備份需另外保留。
- 重置清空原生任務、站內通知與批次／去重引用，並結束目前分頁展示工作階段。新用品 ID 不重用，已顯示的舊通知網址不能定位新用品；也會盡力關閉該 App 的既有系統通知。OS 已接收通知不能保證撤回。
- 保留 profile、通知權限、推播偏好與單位選項；不使用 `?reset=1`，不呼叫廣泛清除。

## 通知展示與獨立待修

10 秒單項通知的排程、權限、正式延後日期、資格與去重未更動。同時最多一筆等待中的 Demo。可使用個人衛生棉或家庭酒精，儲存明天或更晚日期後測試。花花認領的垃圾袋保留原認領者，需依正式接手規則操作，不為展示繞過資格。

**尚未修正的獨立問題：** 自己認領的共享用品，通知點擊仍依共享空間導向「共享清單」，而非「我的清單／共享認領」。本次不以新資料掩蓋或宣稱修復；後續需統一網址產生與 ShoppingView 定位的認領判斷。

多項通知合併仍是後續規劃：同接收者、同空間、同提醒日期合併，用品以 ID 去重；點擊後進該空間清單，不展開全部卡片。本次不新增此功能。

# 期末展示初始資料與安全重置

## 修改範圍

六項資料產生器與用品狀態維持不變。快速重置只調整既有展示管理工具與工具的鎖定失敗提示；不新增另一套重置系統，不修改正式 App 的 UI、Router、BottomNav、Pinia 業務、補貨計算、認領、延後或 5 秒通知排程。

管理工具可以完全不使用；有效 localStorage 仍優先載入，部署不會自動清理資料。以下步驟須由操作者自行啟動；開發與測試不操作使用者現有瀏覽器。

## 手動套用（不會自動操作既有瀏覽器）

允許的精確 origin（Preview 與指定正式站）：

`https://home-restock-app-git-feature-native-browser-n-f5352f-xiedailing.vercel.app`

`https://home-restock-app.vercel.app`

1. 直接開啟指定 Preview／正式站 的 `/?demoSetup=1`；一般設定頁不提供管理入口。
2. 關閉其他補補分頁，包括舊部署版本的分頁與視窗。此工具頁不掛載 App、Router、Pinia 或通知排程。
3. 點「恢復六項展示初始資料」，在一次確認對話框中確認。取消不會備份或重置。
4. 系統自動保留操作前一版本地備份，再執行既有交易。成功後完整導向 `/shopping?notificationDemo=1`，返回原本 App，不停留在管理頁。
5. 若需測試通知，可在購買清單標題按住3秒後放開，主動啟用 Demo。瀏覽器通知權限、提醒偏好重置為產品預設（推播開啟、預設提醒門檻）；這不代表已取得系統通知授權。

可重複此流程回到初始狀態，日期以該次建立當天為準。無須每次下載、勾選或輸入確認文字。「下載目前資料備份」仍可選用，不是重置前置條件。

### 還原操作前資料

初始化會在 `home-restock:v1:presentation-backup` 保留最近一次成功嘗試操作前的完整原始存檔。重新進入操作頁，點「還原上次操作前的資料」並在一次對話框中確認，成功後同樣回到原本 App。恢復用品、空間與 catalog，但不恢復舊 Demo 任務或舊通知中心紀錄。若備份有有效的正式延後日期，正式排程仍可依原規則重建；這不等同於重送舊 Demo。

還原操作本身也會備份當前資料，所以上一份站內備份會被替換。下載的 JSON 是額外離線備份，本版沒有任意 JSON 匯入入口；需要更早備份時，應先驗證格式與資料關聯，再另行安排還原，不直接貼入 localStorage。

## 安全性與限制

- `presentationAccess.js`：指定 Preview／正式站 的一般新版分頁，整個生命週期持有共享 Web Lock；初始化需取得獨占鎖，其他一般分頁存在時拒絕。從 BFCache 返回的頁面強制重載，避免使用失去鎖後的舊 store。
- 初始化再按既有順序以 `ifAvailable` 取得 `bubu-native-reminders` 與 `bubu-items-write`；任一鎖無法取得便拒絕並提示。確認前讀取快照，確認後資料若有變動便拒絕操作，要求重新按鈕確認，避免舊確認覆蓋新資料。
- 不支援 Web Locks 時拒絕初始化。其他未知 origin 不會提供入口，操作 API 同樣拒絕；環境變數無法繞過白名單。
- Web Locks 只能協調有遵守同一協定的程式。較舊部署的已開啟分頁沒有生命週期共享鎖，因此必須先關閉所有舊分頁；不能宣稱完全阻擋舊程式、開發者工具或外部寫入。
- localStorage 不提供跨 key 原子交易。`presentationTransaction.js` 先保存原始備份及 `prepared` 日誌，再寫所有相關 key，最後標記 `committed`。中斷的 prepared 回滾，committed 完成新資料；App／stores 讀取前先復原。只有成功後才回到一般 App。
- 若配額／儲存權限造成回滾也失敗，保留日誌，阻止混合資料載入；恢復儲存空間後重新開啟。不能保證瀏覽器清除整個網站資料、磁碟毀損時仍能復原，離線下載備份需另外保留。
- 重置清空舊原生任務、舊站內通知與批次／去重引用，再建立本輪三則站內歷史通知及衛生紙的去重標記，並結束目前分頁展示工作階段。新用品 ID 不重用，已顯示的舊通知網址不能定位新用品；也會盡力關閉該 App 的既有系統通知。OS 已接收通知不能保證撤回。
- 重置 profile 與通知偏好；保留瀏覽器通知權限與單位選項；不使用 `?reset=1`，不呼叫廣泛清除。

## 通知展示與獨立待修

5 秒單項通知的排程、權限、正式延後日期、資格與去重未更動。同時最多一筆等待中的 Demo。可使用個人衛生棉或家庭酒精，儲存明天或更晚日期後測試。花花認領的垃圾袋保留原認領者，需依正式接手規則操作，不為展示繞過資格。

自己認領的共享用品通知現已導向「我的清單／共享認領」；未認領或其他成員認領的用品導向所屬共享空間。網址產生與頁面定位共用認領判斷，舊通知連結亦依目前用品狀態重新定位，不修改認領或延後資料。

多項通知合併仍是後續規劃：同接收者、同空間、同提醒日期合併，用品以 ID 去重；點擊後進該空間清單，不展開全部卡片。本次不新增此功能。

## 初始鈴鐺三則通知

只在首次建立新資料或操作者手動執行安全初始化時建立；有效舊存檔不自動替換。使用當輪用品與空間ID，皆為本人未讀、未查看的展示歷史紀錄：

1. `「個人」的衛生紙該補貨了`：沿用補貨建議文案函式；預先保存同一筆預測的處理標記，避免啟動後又產生第四則。
2. `「個人」的衛生棉是否已購買？`：依 `specs/001-reminder-restock/spec.md` FR-006 使用詢問文案；點擊進我的清單。本則為 `source: demo`、`previewOnly: true` 的初始歷史紀錄，不代表一般未購買提醒排程已實作，不改衛生棉的加入日期。
3. `花花已認領「家庭」的垃圾袋。`：沿用共享操作文案函式；花花ID引用家庭實際成員，並非self，不執行新的認領操作或批次通知。

共用通知模型僅允許帶有展示標記的 shopping-pending 初始紀錄；不開放新的正式排程類型。通知初始資料來源為 `presentationNotifications.js`，還原操作仍不恢復舊通知任務。

家庭資料維持 `shared: true`，已有花花時依原規則鎖定開關。SwitchTrack 的 disabled 樣式修正為保留 checked 的綠色，只降低透明度，不再把已開啟畫成關閉；關閉且停用時仍為灰色。

延後提醒新增取消按鈕以 grid 高度／間距／透明度過渡，使貼底 sheet 自然向上增高；減少動態效果時不播放。未改日期、5秒排程或認領功能。

本輪驗證：285項完整測試、一般／Demo建置通過。隔離手機瀏覽器確認三則通知刷新不重複、通知內文與點擊路由、家庭開關綠色且checked/disabled、sheet高度265→330px且底部固定（19個中間高度取樣）、減少動態效果；原生5秒通知及既有購買清單回歸通過。現有使用者資料未重置。


## 正式站展示操作

正式站可先正常驗收，不會因部署、登入或長按自動重置。需重置時，先關閉同一網站其他補補分頁，再開啟 https://home-restock-app.vercel.app/?demoSetup=1 ，按恢復六項展示初始資料並確認。沿用自動本地備份、鎖、交易日誌及回復；個人資料與推播偏好一併重置，瀏覽器授權與自訂單位仍保留。Preview 與正式站資料按 origin 分開，不會互相同步。較舊版本分頁可能未遵守鎖協定，因此務必關閉所有舊分頁。

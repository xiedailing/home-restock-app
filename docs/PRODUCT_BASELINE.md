# 補補｜產品與工程基準

> 更新日：2026-10-09。詳細規則見 `specs/001-reminder-restock/spec.md`，每條決策的舊值、新值與原因見 `docs/DECISION_LOG.md`。

## 產品問題
讓發現需要補貨、但不能立刻購買的人，可以低負擔地保留需求，之後完成採買；共同生活時可視需要同步資訊。此定位來自專題文件與訪談（〈前期研究〉：問卷 47 份、訪談 6 位），不可宣稱所有家庭都有相同困擾。

## 已定案（2026-10-09 使用者確認）

### 提醒狀態
- 預計補貨日前 T 天進入「該補貨了」（含第 T 天與第 0 天）；T 預設 5 天，可在設定全域調整（1/3/5/7/14/30）。早於該區間顯示「不需補貨」。
- 預計補貨日早於今天，顯示「補貨時間已過」。
- 在購買清單中時，優先顯示「購買清單中」。
- 提醒關閉一律顯示「未開啟提醒」，不區分「從未設定」與「設定後關閉」。

### 提醒的設定依據
- 新增用品時以提醒開關控制，預設開啟；已移除「不確定」選項。
- 開啟提醒時必填：目前庫存量、下次預計補貨日（最早只能選明天）。
- 每單位可撐天數 ＝（預計補貨日 − 基準日）÷ 庫存量。
- 用品詳情不顯示「補貨週期」欄位，只能編輯下次預計補貨日；修改時以基準日重算每單位可撐天數。
- 用品詳情可隨時開關提醒。關閉時保留資料但不使用；重新開啟時要重新填寫，日期不預填。

### 完成補貨
- 提醒卡片【已補貨】：填數量，日期預設今天、可改。
- 購買清單打勾：填數量（預填待買數量），日期固定為當天，之後可在補貨紀錄修改。
- 提醒開啟時，下次預計補貨日 ＝ 補貨日 ＋ 購買數量 × 每單位可撐天數，四捨五入到整天。使用者不需填寫下次日期。
- 提醒關閉時只新增紀錄，不產生下次日期。
- 不計算剩餘量。只做補貨週期，不做庫存。
- 從歷史紀錄自動學習消耗週期不進 MVP。

### 購買清單
- 待買數量預設 1，可在清單中修改。
- 加入清單後滿 N 天未打勾，提醒「是否已購買？」；N 預設 5 天，可在設定調整。
- 購買清單 Flow 04～06 由組員負責，以上兩條需與組員對齊。

## MVP 核心 Flow
依 FigJam「前期研究分析-整理版」的 MVP Core Flow：
1. Flow 01：新增用品與開啟補貨提醒
2. Flow 02：首頁補貨建議處理（加入待買／已補貨／暫時不用）
3. Flow 03：查看與管理用品（用品詳情、編輯、提醒開關、補貨紀錄）
4. Flow 04～06：購買清單、共享認購與回報（組員負責）

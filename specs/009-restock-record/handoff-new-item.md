# 交接｜新增用品頁（給負責新增用品的組員與她的 AI）

> 日期：2026-10-16。對應 `specs/009-restock-record/spec.md` 的 FR-909，決策見 `docs/DECISION_LOG.md` 的 UT-15、UT-16、UT-28。
> 請先讀完本文件，再讀 spec 009 的 FR-904、FR-909，最後讀現有的 `src/views/AddItemView.vue` 當起點。

## 背景
可用性測試後，「＋」選單的「新增補貨紀錄」進入新的補貨頁（由另一位同學負責）。補貨頁的用品清單裡沒有想要的東西時，使用者點格子裡的「＋新用品」，進入**你負責的新增用品頁**，建立一個用品，回到補貨頁。

關鍵觀念：**這裡新增的是「全域用品」，不屬於任何空間，所有空間都能選。** 所以新增用品頁沒有空間欄位，也沒有提醒、庫存量、預計補貨日、數量、日期，這些全部拿掉。

## 你要做的
新增用品頁（保留路由名稱 `add-item`，路徑 `/items/new`），欄位如下：

| 欄位 | 必填 | 說明 |
|---|---|---|
| 圖示 | 否 | 沿用 `ItemIconEditor`（預設圖示／相簿／拍照）。沒選時，依名稱用 `matchItemIconKey` 比對，比對不到用通用圖 |
| 名稱 | 是 | 長度規則沿用 `limitSpaceName`（中文算 2、英數算 1，上限 16） |
| 類別 | 是 | 選項用 `itemsStore.categoryOptions`（**含使用者自訂分類，不能寫死六個**） |
| 單位 | 是 | 選項用 `UNITS`，另有「自訂」可輸入 |

- 必填欄位的標籤旁加小紅色 `*`。
- **名稱重複（UT-16）**：與現有全域用品（含預設用品）重複時，才顯示純文字提示「此用品已經存在」；沒有重複不顯示任何提示。重複時儲存按鈕變灰不能按。比對規則：忽略前後空白、英文大小寫不分，其餘文字須完全相同。請呼叫 `catalog.isNameTaken(name)`，不要自己寫比對。
- **類別、單位的呈現（建議，不是規定）**：收合成「標籤＋目前值＋箭頭」的列，點開展開選項，一次只展開一個，選好自動收合。專案現有的 `AddItemView.vue` 已有同一種展開面板做法可以沿用。
- **缺必填欄位時的處理（建議）**：儲存按鈕保持可按；缺欄位時按下去，把缺的那一列標籤改成紅色並自動展開第一個缺的欄位，**不顯示錯誤句子**（可用性測試反應畫面字太多）。補上後即時恢復。
- 離開頁面時若已填了內容，沿用現有 `onBeforeRouteLeave` 放棄確認的做法。

## 介面約定（只有這三件事）
補貨頁和你的頁面透過新的 `src/stores/catalog.js` 溝通：

```js
// 從補貨頁進來（補貨頁會做，你不用管）
router.push({ name: 'add-item' })

// 你的頁面
const catalog = useCatalogStore()

catalog.isNameTaken(name)        // → boolean；名稱是否已存在於全域用品（含預設用品）
const item = catalog.addCatalogItem({
  name,            // 已 trim
  iconKey,         // string | null
  iconPhoto,       // string | null（data URL）
  iconManual,      // boolean
  category,        // string
  unit,            // string（自訂單位就是使用者輸入的字）
})                               // → 新建立的全域用品，含 id、createdAt

router.back()                    // 儲存成功後回到補貨頁
```

- `id` 由 store 產生（用 `utils/id.js` 的 `generateId()`），**你的頁面不需要、也不要自己產生 id**。
- 儲存成功後只要 `router.back()`。補貨頁會自己去選好剛新增的用品並顯示 Toast，你不用傳任何東西回去。
- 不要改 `stores/items.js`、補貨頁（`RestockRecordView.vue`）、`SpacePill.vue`。

## 為什麼用 id（給想知道原因的人）
名稱是使用者看到的，而且之後**可以被改**（例如在「用品管理」把「衛生紙」改成「面紙」）。id 是系統給每個用品的固定編號，建立後永遠不變，就像學號和姓名：改名字，學號還是同一個人。

這裡會用到 id 的地方：補貨頁會記住使用者勾了哪些用品，而且從「用品管理」回來時還要還原。如果用名稱記，使用者中途改了名字，記住的東西就對不上、會憑空消失；用 id 記，就算名字改了，還是同一個用品，只是顯示新的名字。

注意：id 不能取代「名稱不可重複」的檢查，那是 `isNameTaken` 的工作，兩件事是分開的。

`src/stores/catalog.js` 由補貨頁那邊的人實作，會先合併一個只有三個介面的最小版本。在那之前：

## 驗收
1. 從補貨頁的「＋新用品」進入新增用品頁；頁面上沒有空間、提醒、數量、日期欄位。
2. 名稱、類別、單位標紅色 `*`；類別選項包含使用者自訂分類。
3. 名稱重複時才出現「此用品已經存在」，且儲存按鈕不能按；沒有重複就沒有任何提示。
4. 缺必填欄位時按儲存，缺的欄位變紅並展開，沒有錯誤句子；補上後恢復。
5. 填好按儲存，呼叫 `addCatalogItem`，成功後回到補貨頁。
6. 有填內容時按返回鍵，會跳放棄確認。
7. 鍵盤可操作，展開的列有 `aria-expanded`。

# Feature 006｜購買清單（草案）

> 草案日：2026-10-11。依 main `b7295cb` 的已完成實作與本次對話中的需求整理。沿用 001 的補貨計算及 003 的用品資料模型；本文件不是改寫既有規格的決策。分歧列於文末，先保留兩邊現況，不視為已定案。

## 目標
讓使用者管理個人待買用品、認領共享用品、調整待買數量、完成補貨與移除清單項目。清單移除與刪除用品資料是不同操作。

## 畫面結構
1. Header：購買清單標題、與個人檔案連動的頭像。
2. 我的清單／共享清單頁籤。
3. 共享清單另有空間篩選，順序沿用空間管理。
4. 狀態小標、可收合的用品卡片；已補貨小標下方有 24 小時說明。
5. 固定底部一鍵操作、Bottom Nav、toast；移除時置中確認視窗。

## 功能需求

### FR-601｜我的清單與狀態分組
- 未加入共享空間：只分「待補貨」「已補貨」，不加「個人」。
- 已加入至少一個共享空間：分「個人待買」「共享認領」「已補貨」。
- 共享認領只含目前使用者認領且尚未補貨的用品；已補貨只含目前使用者完成的用品。
- 任一狀態 0 項時不顯示小標與卡片；整個頁籤無用品時呈現空狀態。
- 狀態小標顯示項數，以＋／−控制收合，區塊使用 0.5 秒抽屜式上下動畫。

### FR-602｜卡片與數量
- 我的清單卡片有勾選框、用品名稱、空間標籤、補貨數量、展開箭頭。
- 共享清單不顯示勾選框；空間名以次要文字呈現，膠囊顯示「尚未認領」、認領者或「已補貨」。
- 未補貨使用 `in-shopping-list` 圖示及 `$accent-soft` 底色；已補貨使用 `in-stock` 圖示及 `$success-subtle` 底色。圓底凹陷陰影引用 `$shadow-inset`。
- 收起保留摘要；展開顯示數量＋／−及移除操作。數量最低 1，修改即時同步摘要與共用待買數量。
- 已補貨整張卡片 opacity 0.68，保留實際完成數量；＋／−及移除按鈕灰色且不可點。
- 同一用品在兩個頁籤的卡片展開狀態各自保留，不互相同步。

### FR-603｜認領、取消及接手
- 尚未認領：按「我要認領」後認領者為目前使用者，加入我的清單；由待認領移到已認領，卡片收起。
- 自己認領：展開顯示紅色「取消認領」。取消後回待認領，標籤「尚未認領」、按鈕「我要認領」；待認領區若收合則展開。
- 其他成員認領：展開顯示淺綠色「接手認領」。成功後改為目前使用者、維持卡片展開，按鈕改「取消認領」。
- 認領／接手 toast：「用品加入「我的清單」」。
- 取消 toast：「已取消認領「空間」的用品」＋「復原」。復原不得覆蓋其他成員已接手的認領。
- 以上目前為同一份本機 store 的示範行為；真實多人同步不在已完成範圍。

### FR-604｜補貨與 24 小時保留
- 只有我的清單可勾選補貨。完成日期為當天，數量採調整後待買數量，建立補貨紀錄並沿用 001 重算提醒。
- 移出有效待買清單後，另以完成時間保留於已補貨區 24 小時。
- 已補貨小字現況：「24 小時後移出購物清單」（用語分歧見 S1）。
- 到期只移除完成展示資訊，不刪用品與補貨紀錄。目前由購買清單掛載、完成時間變動及頁面可見性事件觸發檢查。
- toast：「已補貨「空間」的用品」＋「復原」。已補貨勾選框再點一次，可撤回該次補貨回原分組；共享用品回共享認領。

### FR-605｜移除清單
- 未補貨卡片點「移除用品」先開視窗「移除清單？」；取消、Esc、點背景可關閉，取消預設無綠框。
- 個人：「「用品」將從購買清單移除，用品資料與補貨紀錄仍會保留。」
- 共享：「「用品」將從共享清單移除，所有成員都將看不到此項目，用品資料與補貨紀錄仍會保留。」
- 按鈕「取消」「移除」。確認清除待買、加入日期、認領及完成展示欄位，不刪用品。
- toast：「用品已從購買清單移除」＋「復原」。

### FR-606｜一鍵操作
- 我的清單有待補貨用品時固定顯示「一鍵補貨」，無待補貨用品則隱藏；包含個人待買與自己認領，每項採自身數量。
- 成功 toast 依空間數採用下方「全部標記已買的 Toast 文案」＋「復原」，可一次撤回該批操作。
- 共享清單選特定空間時固定顯示「一鍵認領」，只認領該空間尚未認領用品；無可認領項目停用，選全部不顯示。
- 認領成功 toast 與 FR-603 相同；按鈕位置不隨清單長度改變。

### FR-607｜Toast、復原與導覽
- toast 引用現有 token；有底部一鍵按鈕時移到其上方，間隔 `$space-16`。
- 無復原按鈕淡出 0.3 秒；有復原淡出 0.5 秒。停留時間沿用 `useToast`，目前 5 秒；新 toast 取代舊 toast、離頁失效。
- 購買清單專用 `undoShoppingOperation` 只撤回操作欄位；目前值不同於操作後值則保留後續修改。補貨只撤回該次紀錄，不覆蓋用品名称、分類或後續新增紀錄。
- 頭像 → `/settings/profile?from=shopping`；返回 → `/shopping`。尚未啟用該路徑的共用切頁動畫。
- 首頁與用品詳情已有加入清單、查看清單入口；購買清單卡片尚無用品詳情導覽。
- 購買清單接受 query `?tab=shared&space=<空間 id>`：開啟共享清單並預選該空間（空間不存在或非共享則忽略篩選）；無 query 時預設我的清單。用品詳情【查看清單】對共享空間用品使用此入口（003、RST-09）。

## 實作檔案與範圍限制
- `src/views/ShoppingView.vue`、`src/models/item.js`、`src/stores/items.js`。
- `SettingsEditProfile.vue` 只增加購買清單來源的返回判斷。
- 不修改其他頁面的復原呼叫、共用 App.vue 動畫規則、tokens 與舊規格。
- 資料與完成操作暫存在記憶體，不保證重新整理、跨裝置或真實多成員共享。
- 「家庭／小明認領垃圾袋 2 包」為展示資料，不是正式帳號資料。

### 全部標記已買的 Toast 文案

以此次成功補貨的用品與其所屬空間 ID 計算，不包含未成功處理的用品。

- 1 個空間：`已補貨「家庭」的 3 項用品`。
- 2 個空間：`已補貨「家庭」、「公司」的 3 項用品`，空間名稱依此次處理順序列出。
- 3 個以上：`已補貨 3 個空間，共 8 項用品`，顯示實際空間數與用品數，不列空間名稱。
- 保留「復原」按鈕；顯示時間與樣式引用共用 `useToast` 與 `AppToast`。

- 購買清單卡片「我要認領」圖示使用 `fa-regular fa-hand`；接手維持 `fa-solid fa-arrow-right-arrow-left`。

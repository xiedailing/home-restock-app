# Feature 011｜補貨明細（用品詳情改版）（草案）

> 草案日：2026-10-17。決策 UT-36 見 `docs/DECISION_LOG.md`〈決策紀錄｜可用性測試修改（2026-10-15）〉。
> 本規格改版 `specs/003-item-detail/spec.md` 的用品詳情頁，並取代其中的部分條文（見「取代的既有規則」）。狀態標記規則沿用 `specs/010-inventory-list/spec.md`；推算與提醒開關沿用 `specs/009-restock-record/spec.md` FR-912、FR-913。

## 目標
把頁面定位成**「一個用品的補貨帳本」**，呼應專案核心：以記帳的方式記錄每一次補貨。頁面只留下需要的資訊：這個用品是什麼、現在的狀態、預計補貨日、補貨紀錄、以及記錄補貨與購買清單兩個動作。名稱、圖示、分類、單位屬於全域用品，統一到「設定 > 用品管理」編輯。

## 名詞
- **補貨明細**：原「用品詳情」頁。路由 name `item-detail`、路徑 `/items/:id` 不變。
- **提醒卡**：頁面中間列出補貨提醒開關、預計補貨日、上次補貨的卡片。

## 現況與問題
- 狀態被說三次：摘要卡右上角 pill、提醒卡標題、提醒卡副標題；加上橘、綠（圓圈、相機角標）、紅（提醒卡圖示）四種顏色。
- 開關夾在資訊列最後一列；資訊列標籤（14px 灰字）不好讀。
- 「基本資訊」直接改空間用品的分類、單位、空間，**不會同步全域用品**，之後用品管理改分類時會被覆蓋，兩邊對不上；改「所屬空間」時若目標空間已有同一個全域用品，`updateItem` 會丟錯，`changeWithUndo` 沒有接住。
- 頁面標題「用品詳情」是資料庫語言，沒有呼應記帳的定位。

## 功能需求

### FR-1101｜頁面名稱
- 頁首 `<h1>` 與路由 `meta.title` 改為「補貨明細」（瀏覽器分頁標題為「補貨明細｜補補」）。
- 路由 name、路徑、程式與檔案名稱都不改。

### FR-1102｜頁首與「⋯」選單
- 頁首：左側返回（不變）、中間標題、右側**「⋯」**（44px 圓形按鈕，樣式與返回鈕對稱；`aria-haspopup="menu"`、`aria-label="更多"`）。移除垃圾桶。
- 選單做法同補貨頁的「⋯」：錨定在按鈕下方的 popover、點外面或 Esc 關閉（Esc 後焦點回到按鈕）、第一項自動取得焦點、Tab 離開時關閉。
- 選單項目：
  1. **用品管理**（格狀圖示，同補貨頁）：前往 `item-management`，帶 `?from=detail`（FR-1109）。
  2. 分隔線。
  3. **刪除用品**（紅字，垃圾桶圖示）：開啟既有的刪除確認視窗；確認、復原與導回「我的用品」的行為都不變（003 FR-309）。

### FR-1103｜摘要卡
- 內容：用品圖示（52px）、名稱、「空間・分類」、右上角狀態標記。
- 狀態標記沿用 `specs/010-inventory-list/spec.md` FR-1001、FR-1002，位置不變；用品圖示依提醒狀態（010 FR-1005）。
- **名稱與圖示不可編輯**：移除名稱旁的鉛筆與行內改名、圖示上的相機角標與「更換用品圖示」（`ItemIconEditor` 在詳情頁不再使用，元件本身仍供新增用品與用品管理使用）。圖示圓圈不可點。
- 名稱、圖示、分類一律在「設定 > 用品管理」編輯，會同步到各空間（`GlobalItemEditor`）。

### FR-1104｜提醒卡（設定頁風格列表卡）
- 一張卡片，沒有區塊標題、狀態標題、狀態圖示、副標題。狀態只由摘要卡的標記表達。
- 每列高 52px；標籤 16px、顏色 `$text-main`（同設定頁列標籤）；數值 16px 粗體。
- 列的順序與內容：
  1. **補貨提醒**＋開關：整列是一個 `role="switch"` 按鈕（觸控區為整列）。開關樣式、行為與確認沿用 003 FR-304／FR-305、009 FR-913：關閉要跳確認視窗（DET-22），開啟直接用紀錄重算；開啟與關閉都不顯示 Toast。
     - **確認視窗文案修正**：原本寫「不會再出現在首頁的補貨提醒」「重新開啟時需要重新設定庫存量與下次預計補貨日」，兩句都過時了（首頁已移除；009 之後重新開啟是直接用紀錄重算）。改為「關閉後，「{名稱}」不會再提醒補貨，也不會顯示預計補貨日。之後重新開啟，會用補貨紀錄重新推算。」
  2. **預計補貨日**：提醒狀態為 `notNeeded` 時標籤是「下次預計補貨日」，其餘是「預計補貨日」。提醒關閉時不顯示（001 FR-005）。
     - 提醒狀態是「該補貨了」（`overdue`、`dueSoon`）時，數值用暖橘色 `$accent-text`（同 pill 字色，不用紅色）；其他狀態維持黑色。
     - 今天就是預計補貨日時，數值後面加「（今天）」，例如 `2026/10/17（今天）`（取代 003 DET-10 的獨立一行「今天是預計補貨日」）。
  3. **上次補貨**：最新一筆紀錄的日期；沒有紀錄顯示「尚無紀錄」。
- **紀錄涵蓋不足兩個不同日期時**（009 FR-913）：卡片仍然顯示，版面與其他狀態一致；沒有「補貨提醒」開關列；「預計補貨日」的值是灰色（`$text-sub`、一般字重）的「再補貨 N 次後預估」（N ＝ 還差幾個不同日期，最少 1），並顯示「上次補貨」。取代原本孤立的一行提示「再補貨 1 次，就能推算下次補貨日」。
- 不顯示倒數天數（沿用 2026-10-15 的決定）、不顯示延後提示（FR-1108）、不顯示「購買清單」資訊列（已在清單由摘要卡標記與按鈕表達）。

### FR-1105｜主要操作（照 Figma「Actions」902:7077）
兩顆等寬按鈕，高 48px、間距 8px：
| 位置 | 按鈕 | 樣式 |
|---|---|---|
| 左（次要） | 未在清單：**加入清單**；已在清單：**查看清單**。前面都有清單圖示（`fa-clipboard-list` 14px，同底部導覽） | 底色 `$primary-subtle`、字色 `#244f34`（Figma `color/brand/dark`）15px 中等、陰影同 Figma Soft UI Elevation S |
| 右（主要） | **記錄補貨**，前面是＋圖示 | 底色 `$primary-green`、白字 16px 粗體、陰影同 Soft UI Button Primary |
- 位置與主次與原本相反（原：記錄補貨在左、灰色次要；加入清單在右、深綠主要）。
- 行為不變：記錄補貨開啟 `RestockSheet`（003 FR-306）；加入清單（003 FR-308）；查看清單的導向沿用 RST-09（個人去 `/shopping`，共享空間去 `/shopping?tab=shared&space=<id>`）。
- Figma 的文字寫「加入購物清單」，這裡沿用現有的「加入清單」（較短）。

### FR-1106｜補貨紀錄
- 區塊位置在按鈕下方（原本在「基本資訊」之後）。
- **每列右側加 `>` 箭頭**（`fa-chevron-right` 12px、`$text-disabled`），提示點進去可以編輯或刪除；編輯 Sheet、刪除與復原、「查看全部 ›」（超過預覽筆數）都不變（003 FR-307）。同一個列元件也用在完整紀錄頁（`item-records`），一併加箭頭。

### FR-1107｜移除「基本資訊」
- 刪除「基本資訊」區塊與 `BasicInfoSection.vue`，詳情頁不再能改所屬空間、分類、補貨單位。
- 空間與分類以**唯讀**方式顯示在摘要卡的「空間・分類」；單位顯示在補貨紀錄的「+1 包」；分類與單位到「設定 > 用品管理」改。
- 代價：**使用者無法把用品搬到另一個空間**（替代做法：到新空間記一筆補貨，再刪除舊的）。

### FR-1108｜不做延後提醒（暫時不用補貨）
- spec 005 的「暫時不用補貨」原本只在首頁提醒卡提供（005 SNZ-05：用品詳情不提供入口）；首頁移除後（UT-01）沒有任何入口，**本次不補回入口**，列為未來展望，005 標為停用。
- 系統誤報（提醒「該補貨了」但實際還不需要）時，使用者的做法：
  1. 什麼都不做，**等實際購買後再按「記錄補貨」**，用實際購買日記錄，系統用全部紀錄重算（FR-912）；
  2. 或用開關關閉這個用品的提醒。
- 因為沒有推播，誤報只是列表與詳情上的標記，代價低；沒有的話提醒狀態維持原判斷（`getReminderStatus` 不看 `snoozedUntil`，不改）。
- **待清理（首頁清理時一併處理）**：`snoozeReminder`、`isSnoozed`、`SNOOZE_DAYS`、`restockReminders`（`stores/items.js`、`models/item.js`），以及資料欄位 `snoozedUntil` 的清除邏輯；`StatusCard` 的延後提示隨本規格改寫自然移除。欄位本身可保留以相容舊存檔。

### FR-1109｜從補貨明細進入用品管理，返回回到補貨明細
- 「⋯ → 用品管理」前往 `item-management`，帶 `?from=detail`。
- 用品管理頁（`SettingsItemsView.vue`，組員負責）的返回鈕：`route.query.from` 是 `restock` 或 `detail` 時用 `router.back()`（原本只認 `restock`）；返回鈕的 `aria-label` 依來源為「返回補貨紀錄」或「返回補貨明細」，其他情況維持「返回設定」。分類頁（`SettingsItemCategory.vue`）已在上一頁是用品管理時用 `router.back()`，不需再改。

## 驗收
1. 頁首標題是「補貨明細」，瀏覽器分頁標題是「補貨明細｜補補」；右上角是「⋯」，沒有垃圾桶。
2. 「⋯」選單有「用品管理」與紅字「刪除用品」；Esc、點外面關閉，Esc 後焦點回到按鈕；刪除仍有確認視窗、5 秒內可復原並導回「我的用品」。
3. 「⋯ → 用品管理」前往設定的用品管理；按返回回到補貨明細（含從分類頁再返回兩次的路徑）；從設定進入用品管理的返回仍回設定。
4. 摘要卡沒有鉛筆與相機角標，名稱與圖示不可點；右上角標記與「我的用品」列表相同（010 的驗收 1～6）。
5. 提醒卡第一列是「補貨提醒」與開關，樣式同設定頁；關閉要跳確認、開啟直接重算、都沒有 Toast；整列都可以點。
6. 預計補貨日：「該補貨了」（含逾期）時是暖橘色，其他狀態黑色；今天是預計補貨日時顯示「（今天）」；提醒關閉時不顯示預計補貨日。
7. 紀錄不足兩個不同日期：卡片仍在、沒有開關列，預計補貨日顯示灰色「再補貨 1 次後預估」，仍顯示上次補貨；補到第二個不同日期後，開關與預計補貨日出現。
8. 按鈕：左邊「加入清單」或「查看清單」（有清單圖示，淡綠底深綠字），右邊「記錄補貨」（＋、深綠）；等寬、高 48px；行為與導向不變。
9. 補貨紀錄在按鈕下方，每列右側有 `>`；點列可編輯與刪除並可復原；完整紀錄頁同樣有箭頭。
10. 沒有「基本資訊」區塊；空間與分類顯示在摘要卡；單位顯示在紀錄；程式裡沒有 `BasicInfoSection`。
11. 名稱很長（20 字）、360px 寬：摘要卡名稱區不被擠壞，標記固定在右上角，無橫向捲動。
12. 回歸：記錄補貨、加入與查看購買清單、刪除用品與復原、補貨紀錄編輯、提醒開關關閉確認都與改版前一致；主控台無錯誤。

## 未決與不做
- **不做延後提醒**（FR-1108）；005 與相關死程式碼待首頁清理時處理。
- **孤兒用品**：全域用品被刪除（各空間用品會保留）或舊資料遷移時沒配對上（`catalogId` 為 `null`）的空間用品，名稱與圖示原本能在詳情頁改，本次移除後**哪裡都改不了**。不常見（要先在用品管理刪掉某個全域用品），目前接受；若要處理，最小做法是「刪除全域用品前，有關聯的空間用品就警告」，會動到組員的檔案，展示前不做。
- 改名稱與圖示的路徑變長：「⋯ → 用品管理 → 分類 → 用品」共 4 步，目前接受。
- 空間與分類在詳情只讀；無法搬移用品到其他空間（FR-1107）。
- 設計稿：只有 HTML 預覽，沒有 Figma 稿。

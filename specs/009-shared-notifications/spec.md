# 通知頁規格

## 實作階段與範圍
- 第二階段：通知 UI、文案格式及空狀態。沿用現有鈴鐺入口、`/notifications` 路由、通知 Store 與 localStorage。
- 第三階段待確認：事件資料串接、去重、60 秒合併、取消認領、跳轉例外、刪除提示及保留期限流程調整。
- 下述為最終目標規則，不表示資料整合已全部完成。不得改補貨日期計算、核心用品模型，或重構我的用品／購買清單。

## 入口及版面（第二階段）
- 共用 `SharedNotificationsMenu` 鈴鐺入口維持原尺寸與樣式，點擊前往通知頁，不開浮動面板。`ProfileAvatarMenu` 保留相容包裝。
- 標題「通知」，左上返回原入口；無紀錄時回我的用品。沿用既有隱藏底部導覽列設定。
- 通知依建立時間由新到舊，可捲動查看。卡片維持 Soft UI 的 `card-bg`、`radius-card`、`shadow-card`，灰線使用 `border-color`。
- 左側保留通知類型 Icon，以鈴鐺為尺寸基準：24×24px 區塊、22px 字級。可沿用用品圖示資源，但不改動共用用品圖示元件。
- 四種類型：該補貨了（bell）、已認領（hand）、已接手（arrow-right-arrow-left）、已補貨（circle-check）。事件仍依文字區分。
- 日期／時間對齊文字第一行；當天 HH:mm，其他日期 MM/DD，按裝置本地日期判斷。
- 多項補貨品名固定在「：」後換行；標題與長內容可自然換行，不強制單行造成窄螢幕溢出。

## 已讀／未讀（第二階段沿用）
- 未讀：`primary-soft` 淺綠底＋`font-weight-medium` 稍粗字重。
- 已讀：`card-bg` 白底＋`font-weight-regular`，不降低文字透明度。
- 通知卡片不顯示未讀圓點，左側 Icon 保留。
- 點擊單筆標記該筆 read，返回後白底；已讀仍可點擊。進頁不將所有通知標為 read。
- 標題右側提供「全部已讀」，使用購買清單批次補貨按鈕相同的淺綠底、圓角、字級與陰影 token。點擊僅將目前可查看的所有通知標為已讀並保存，不刪通知、不跳轉；空清單時點擊不做變更。
- 原入口的 seen 狀態與 read 分開：進頁清除鈴鐺圓點不等於全部已讀。
- 已讀狀態由既有 localStorage 保存。

## 文案規則（第二階段格式函式）
正式通知必須使用事件當時的成員名稱、空間名稱、用品名稱快照；不將以下範例寫死為正式事件。

### 該補貨了
| 數量 | 範例 |
| --- | --- |
| 1 項 | 「家庭」的衛生紙該補貨了 |
| 2 項 | 「家庭」有 2 項用品該補貨：衛生紙、洗衣精 |
| 3 項 | 「家庭」有 3 項用品該補貨：衛生紙、洗衣精、垃圾袋 |
| 4 項以上 | 「家庭」有 5 項用品該補貨：衛生紙、洗衣精… |

### 已認領／已接手／已補貨
- 1～2 項列完整品名，3 項以上僅用品總數。
- 小明已認領「家庭」的衛生紙。
- 小明已認領「家庭」的衛生紙、酒精。
- 花花已接手「家庭」的酒精。
- 花花已接手「家庭」5 項用品。
- 小明已補貨「家庭」3 項用品。
- 既有正式通知缺少結構化欄位時顯示原 message，不猜測操作者或重新查詢當前名稱改寫歷史。只在 60 秒內可更新合併中的內容。

## 空狀態（第二階段）
- 標題：「目前沒有通知」
- 說明：「有新的共享用品動態時，會顯示在這裡。」
- 不增加操作按鈕。

## 觸發與接收對象（第三階段）
- 該補貨了：共享用品符合既有補貨提醒條件與設定時通知相關成員，沿用既有狀態計算。
- 已認領／已接手／已補貨：由其他共享成員實際操作觸發，排除操作者本人。
- 個人空間購買行為不產生共享通知；取消認領不產生通知。
- 穩定事件 ID 去重，同一事件不得重複通知。

## 60 秒合併及取消（第三階段）
- 必須同操作者、同共享空間、同類型，且在第一筆事件後固定 60 秒內；不同類型分開。
- 第一筆即建立；後續加入不重設起點，超過 60 秒新建。批次操作可直接建立一筆，相同用品 ID 同批只算一次。
- 持久化第一筆事件時間、批次鍵、事件 ID、用品 ID／名稱快照、操作者與空間快照。重整後仍可判斷窗口。
- 更新已讀批次維持 read／seen，不重新設為未讀；窗口結束後文字與建立時間固定。
- 窗口內取消認領：移除對應用品，整批清空則移除通知；超時不改歷史。取消不發新通知，復原行為須與共用操作確認。

## 跳轉與刪除例外（第三階段）
| 類型 | 目的地 |
| --- | --- |
| 該補貨了、已補貨 | 我的用品 → 對應空間 |
| 已認領、已接手 | 購買清單 → 共享清單 → 對應空間 |

- 單項、多項規則相同，不進詳情；顯示最新資料，不重新執行操作、不改用品或補貨紀錄。
- 無論尚未、部分、全部已補貨，或再次需要補貨，正常跳轉，不顯示「此通知的用品皆已補貨」。
- 先確認空間存在及權限，失敗留在通知頁，Toast「此空間已不存在或無法查看」。
- 空間有效後以通知內用品 ID 檢查：全部已刪除留在通知頁，Toast「此通知的用品皆已刪除」；部分已刪除正常跳轉，Toast「此通知有部分用品已刪除」。
- 每次至多一則 Toast，空間提示優先。用品刪除不等於已補貨，不用當前名稱配對推測舊用品 ID。
- 保留舊通知文字與建立時間；既有缺用品 ID 的舊資料不能可靠執行刪除判斷，需另行確認遷移策略。

## 保存與六個月保留（第三階段整理）
- 沿用 `sharedNotifications`、`home-restock:v1:shared-notifications`，重新整理保存通知、已讀與批次資料。
- 保留最近六個曆月，已讀及未讀一律移除過期通知；截止邊界保留，月底取目標月最後一天。
- 可在 App／通知頁開啟時清理，不需要背景排程。不提供手動刪除或全部清除。
- 通知資料獨立於用品、購買清單及補貨歷史，清理不得影響其他資料。

## 假資料與現階段限制
- 第二階段沿用 `source=demo` 假資料預覽，不把假資料改為正式事件，也不修改實際用品。
- 既有 scroll 假資料可用多項品名預覽文字格式，呈現層補足預覽操作者，不回寫歷史存檔。
- `source=event` 為同一瀏覽器內操作資料；目前尚無跨裝置同步或多人後端，不能宣稱其他裝置已收到。
- 本階段不更動現有資料串接：舊補貨 Toast、已補貨跳轉、背景清理、空間過濾等舊實作仍待第三階段依上列新規則替換。

## 後續驗收
- 第二階段：手機／桌機卡片、長文換行、兩種已讀外觀、四類文案、空狀態、入口路由。
- 第三階段：對應空間跳轉、事件去重、固定 60 秒邊界、不同成員／空間／類型不混合、取消撤回、讀取與批次重整保存、用品刪除與權限例外、六個月清理。
- 不影響現有補貨提醒與認領流程，執行 `npm run build`。

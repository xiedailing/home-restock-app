# Feature 003｜用品詳情頁（修訂版 1）

> 草案日：2026-10-09；修訂日：2026-10-10（決策 DET-01～DET-21）。業務規則以 `specs/001-reminder-restock/spec.md`（以下簡稱 001）為準，本規格定義用品詳情與補貨紀錄的畫面、互動，以及 001 FR-003～FR-005 的程式落地。
> 決策舊值、新值與原因見 `docs/DECISION_LOG.md`〈Feature 003〉。

## 目標
讓使用者從「我的用品」點進一項用品，查看狀態、修改基本資訊、開關提醒、編輯下次預計補貨日、記錄補貨，並管理補貨紀錄。**不包含「暫時不用」、購買清單打勾、首頁補貨卡片與資料持久化。**

## 入口與路由
| 路由 | 名稱 | 內容 |
|---|---|---|
| `/items/:id` | `item-detail` | 用品詳情（隱藏 Bottom Nav） |
| `/items/:id/records` | `item-records` | 補貨紀錄完整列表（隱藏 Bottom Nav） |

- 入口：我的用品列表點一列（左滑展開時點擊只收回，維持現況）；新增用品建立成功後（取代 ADD-06，改回 Figma Flow 01：進詳情並顯示 Toast「已新增用品」）。
- 用品不存在（例如已刪除、重新整理後 id 失效）→ 導回 `/inventory`。
- 返回：有上一頁時 `router.back()`，否則回 `/inventory`。

## 畫面結構（由上到下，依 Draft A）
1. **App Bar**：返回、標題「用品詳情」、右側垃圾桶（刪除用品）。
2. **用品摘要卡**：圖示（依名稱判斷，同 002 FR-203）、名稱＋鉛筆（inline 改名）、「空間・分類」、狀態徽章。
3. **狀態卡**：依 001 FR-001 狀態顯示（FR-302）。
4. **基本資訊**：所屬空間、分類、補貨單位（inline 選擇，同 002）。
5. **補貨資訊**：補貨提醒開關、下次預計補貨日（僅提醒開啟時）、上次補貨。
6. **補貨紀錄**：最新 4 筆＋「查看全部 ›」；沒有紀錄時見 FR-307。

## 功能需求

### 共通｜Toast
- 同時只顯示一個 Toast；新的取代舊的，舊的不能再復原（DET-07）。
- 離開詳情頁即失效；刪除用品例外（DET-20）。
- 基本資訊與改名的 Toast 都提供「復原」（DET-15）；「已開啟補貨提醒」例外（DET-08）。

### FR-301｜用品摘要與改名
- 點鉛筆 → 名稱變成 inline input（Figma 966:8254），右側 ✓。
- 離開輸入框、按 Enter 或點 ✓ 時儲存；不在輸入途中自動儲存，避免 Toast 重複出現、復原只回到一半的名稱（DET-06）。長度規則同 002（中文 2、英數 1，上限 16）。
- 名稱為空：不儲存，輸入框暖橘外框＋提示「請輸入用品名稱。」，留在編輯狀態（Figma 1208:13658）。
- 儲存成功：圖示依新名稱重新判斷（例：洗衣精 → 洗衣粉，改為通用圖）；Toast「已更新用品名稱」＋「復原」。
- 狀態徽章文字使用 `STATUS_LABELS`（與我的用品列表一致，DET-17）。

### FR-302｜狀態卡

| 該補貨了 | 該補貨了／這項用品已進入提醒時間。（DET-18） | 「距離下一次補貨還有 NN 天」計數＋預計補貨日 | 【已補貨】【＋ 加入清單】 |

- 視覺依 001 D6：「該補貨了」白底＋暖橘外框；「補貨時間已過」淡暖橘底＋明顯徽章；不使用紅色與驚嘆號。
- 計數至少兩位數（05）；超過 99 天顯示實際數字，卡片自動放寬，不顯示「99+」（DET-16）。
- 「該補貨了」剩 0 天：不顯示「還有 00 天」，改為「今天是預計補貨日」（DET-10）。

### FR-303｜基本資訊
- 所屬空間、分類、補貨單位：點列 → 下方 inline 展開，元件與選項同 002（含「＋ 新增空間」Sheet、自訂單位）。
- 選取即自動儲存並收合；Toast「已更新所屬空間／分類／補貨單位」＋「復原」（Figma Toast / 已更新分類）。
- 不修改週期、日期或狀態；補貨單位只影響數量顯示。

### FR-304｜補貨提醒開關（001 FR-005，Draft A～C）
- **關閉**：不跳確認，立即生效；`reminderEnabled = false`，保留 `nextRestockDate`、計算基準與 `daysPerUnit`；用品若在購買清單中仍留在清單。Toast「已關閉補貨提醒」＋「復原」，點復原直接恢復，不跳 Sheet。
- **開啟**（開關或狀態卡【開啟補貨提醒】）：開「設定補貨提醒」Sheet（Figma 1204:11069）：家裡目前有多少？（預設 1）＋下一次預計什麼時候補貨？（快選下週／兩週後／下個月＋日期列，**日期為空、不預填**，最早明天）＋【完成】。
  - 完成：`reminderEnabled = true`、`nextRestockDate`、計算基準（今天，庫存量）、`daysPerUnit` 重新計算、`reminderEnabledDate = 今天`；Toast「已開啟補貨提醒」，**不提供復原**（復原等於關閉，直接用開關即可；DET-08）。
  - 取消（下滑、點背景）：開關回到關閉，不儲存（F3）。
- Toast 顯示時間沿用刪除用品的 Undo Toast（5 秒）。

### FR-305｜下次預計補貨日（001 FR-002、D1-a，Draft D）
- 只在提醒開啟時顯示；點列 → 日期 Sheet，**預設帶入目前日期**，快選＋日曆，最早明天；不出現庫存量。
- 目前日期早於明天（補貨時間已過，或剩 0 天）：不預選任何日期，選定後才能按【完成】（DET-01）。
- 完成：更新 `nextRestockDate`；`daysPerUnit =（新日期 − reminderBaseDate）÷ reminderBaseQuantity`；基準日不變。Toast「已更新下次預計補貨日」＋「復原」。
- 「上次補貨」只顯示最新一筆紀錄的日期，沒有紀錄顯示「—」；不可點；要修改請到補貨紀錄（DET-13）。

### FR-306｜記錄補貨（001 FR-003 卡片入口）
- 狀態卡【已補貨】→「記錄補貨」Sheet（Figma 959:7879）：補貨日期（預設今天，顯示「今天・2026/10/09」，點擊開日期 Sheet）、補貨數量（Stepper，預設 1、最小 1，單位取自用品）、【確認補貨】。
- 確認：
  - 新增紀錄（日期、數量），`lastRestockDate` 更新為最新紀錄日期。
  - 移出購買清單（`inShoppingList = false`，待買數量清除）。
  - 提醒開啟，且新紀錄成為「重算依據」（見下方〈最新一筆與重算依據〉）：`nextRestockDate = 補貨日 + round(數量 × daysPerUnit)`；計算基準更新為（補貨日，數量）。
  - 提醒開啟，但新紀錄不是重算依據（補登較早的補貨）：只新增紀錄，不重算（DET-04）。
  - 提醒關閉：只新增紀錄。
  - Toast「已記錄補貨」＋「復原」（復原還原整筆變更）。
- 補貨日期最晚今天，不可選未來日期；編輯補貨紀錄同（DET-12）。

#### 最新一筆與重算依據（FR-306、FR-307 共用；DET-03、DET-04）
- **最新一筆**：日期最晚的紀錄；同一天有多筆時，以較晚新增的為準（紀錄依新增順序排列，不另存時間）。
- **重算依據**：最新一筆，且日期不早於 `reminderEnabledDate`（最近一次開啟提醒的日期）。
- 沒有重算依據時（紀錄全刪，或剩下的紀錄都早於開啟提醒日）：保留目前的 `nextRestockDate` 與計算基準，不重算。
  - 例：8/1 有一筆紀錄；10/10 重新開啟提醒；10/20 補貨後再刪掉 10/20 那筆 → 8/1 早於 10/10，不能拿來重算，保留目前日期。

### FR-307｜補貨紀錄
- 詳情頁區塊：依日期新到舊最多顯示 5 筆（「YYYY/MM/DD　補貨 N 單位」）；**超過 5 筆**才在右上顯示「查看全部 ›」→ `/items/:id/records`（DET-09）。
- 詳情頁區塊的紀錄也可以點，和完整列表一樣開「編輯補貨紀錄」Sheet。
- 沒有紀錄：區塊顯示「還沒有補貨紀錄」一行灰字（Figma 無對應畫面，DET-19）。有起點時改為只顯示起點列。
- **開始追蹤起點**（DET-21）：最近一次開啟提醒（新增用品時或之後在詳情開啟）顯示為一列「YYYY/MM/DD　開始追蹤・家裡有 N 單位」。
  - 依日期排入列表；與補貨紀錄同一天時排在下方。空心圓點、灰字，不可點、不可編輯。
  - 不算補貨紀錄：不計入「共 N 筆」與 5 筆上限，不影響「上次補貨」與重算。詳情只顯示 5 筆時，比第 5 筆更早的起點不顯示。
  - 重新開啟提醒時改成新的起點，舊起點不保留；從未開啟提醒的用品沒有起點。
- 完整列表頁（Figma 1246:7839）：標題「補貨紀錄」、用品名稱＋「共 N 筆」、全部紀錄、底部說明「點選一筆紀錄，可修改補貨日期與數量」。
- 點一筆 →「編輯補貨紀錄」Sheet（Figma 1246:13995）：補貨日期、補貨數量、【儲存變更】、【刪除此筆紀錄】（危險色文字按鈕）。
  - 儲存：Toast「已更新補貨紀錄」＋「復原」。刪除：不另跳確認，Toast「已刪除補貨紀錄」＋「復原」（Figma 1246:14153）。
  - 001 FR-004：修改或刪除後，若重算依據改變或被修改，提醒開啟時以新的重算依據重算：`nextRestockDate = 最新日 + round(數量 × daysPerUnit)`，計算基準＝（最新日，數量）。修改較舊的紀錄不影響；沒有重算依據時保留目前日期（見上方）。
  - `lastRestockDate` 一律等於最新紀錄日期（全刪時為 null）。

### FR-308｜加入購買清單（需與組員對齊，001 FR-006）
- 【＋ 加入清單】：`inShoppingList = true`、待買數量 1、加入日期＝今天；狀態變「購買清單中」；Toast「已加入購買清單」＋「復原」（Figma 948:7773）。
- 待買數量沿用組員 `ShoppingView.vue:21,33` 已讀取的 `quantity`，不另取名（DET-11）；新增 `addedToShoppingListDate`（見資料模型）。購買清單頁的顯示與打勾由組員負責，本次不改 `ShoppingView.vue`。

### FR-309｜刪除用品
- 垃圾桶 → 確認 Dialog（同我的用品刪除確認，文字沿用）→ 刪除後回到我的用品，顯示既有的刪除 Toast＋「復原」。
- 我的用品的 Undo 目前只存在頁面內；改為由 store 保存「最近一次刪除」，兩個入口共用；從詳情刪除後回到我的用品仍可復原（DET-20）。

## 資料模型與 store 變更
- `item.js` 新增欄位：`quantity`（**待買數量**，不是庫存量；null，加入清單時 1，移出清單時清除；DET-11）、`addedToShoppingListDate`（null）、`reminderEnabledDate`（最近一次開啟提醒的日期，null；補貨後不變，與 `reminderBaseDate` 不同）、`reminderEnabledQuantity`（開啟提醒時填的庫存量，null；起點列使用，DET-21）。
  - 寫入時機：新增用品時開啟提醒（`AddItemView.vue`）、「設定補貨提醒」Sheet 完成；關閉提醒時保留，Toast 復原時一併恢復。
- `stores/items.js`：
  - 改寫 `completeRestock(id, { date, quantity })` 為 FR-306 公式；移除「無週期時推算、最少 7 天」（001 差異表 `items.js:63-64,69`）。
  - 新增 `updateRestockRecord`、`removeRestockRecord`（FR-307 重算）、`setReminder`（開啟／關閉／復原）、`updateNextRestockDate`（FR-305）。
  - 新增最近一次刪除的 snapshot 與 `undoRemoveItem`（FR-309）。
- 計算集中在 `models/item.js` 的純函式（`calcDaysPerUnit`、`calcNextRestockDate`），方便之後補測試。
- 示範資料：提醒開啟的用品補上計算基準，讓舊資料也能完成補貨（DET-02）：基準日＝`nextRestockDate − cycleDays`、基準數量 1、`daysPerUnit = cycleDays`、`reminderEnabledDate`＝基準日。
  - 不以「今天」當基準：垃圾袋預計日為今天 −2，會得到每包 −2 天。
- 不處理 `cycleDays`：保留欄位但不再讀寫（001 D3）。
